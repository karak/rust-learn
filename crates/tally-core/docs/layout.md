# tally-core のコード配置

**このクレートのどこに何を置くか、なぜそこなのか** の正本。
コードを足す・動かす前にここを読む。

**ここに書くのはクレートの性質だけ。** 次のものは書かない。

- 進捗・現在地 → `docs/handoff.md`
- 学習の進め方、読む順序といった **学習者への指示** → `docs/curriculum.md`
- 他言語との差分などの **学びの内容** → `docs/learning-log.md`
- CLI の関心事（引数・整形・終了コード）→ `crates/tally/docs/layout.md`
- **利用者に対する出力の外部契約** → `crates/tally/docs/output-format.md`
- 公開 API の形をどう決めたか → `docs/adr/0004-*` と `docs/adr/0005-*`

---

## このクレートの境界

**2 つの不変条件で定義されている。破るときは新しい ADR が要る。**

1. **`clap` にも `anyhow` にも依存しない。**
   引数解釈とエラーの束ね方は CLI の関心事である。
   `cargo tree -p tally-core` で確かめられる
2. **ファイルを開かない。** `tally_reader` が `impl BufRead` を受け取るのが
   唯一の I/O 境界で、開くのは呼び出し側の仕事

`TallyError::OpenInput` があるのは 1 の例外ではない。**このクレートは何も開かず**、
呼び出し側の「開けなかった」を同じ分類に載せるための置き場所として持っている。

## ファイルの配置

| パス | 役割 | 置いてよいもの | 置いてはいけないもの |
| --- | --- | --- | --- |
| `src/select.rs` | キーの抽出と正規化 | `Key`、`Selector`、正規化の純粋関数 | **どの行が参加するかの判断**、欠損の扱い、I/O |
| `src/count.rs` | 度数の集計と結果の表現 | `Counter`、`Entry`、`Report`、`tally_reader` | 抽出規則、整形、ファイルを開く操作 |
| `src/error.rs` | 失敗の型 | `thiserror` の型、抜粋の切り詰め | `anyhow`、終了コード、hint（CLI の語彙） |
| `src/lib.rs` | 公開面の宣言 | `mod` 宣言、`pub use`、クレートの doc | 実装 |
| `docs/` | このクレートの構造の説明 | 配置・設計判断・その理由 | 進捗、日付つきの記録 |

**判断に迷ったら**: それは「**どの行が参加するか**」「**参加する行がどうキーを産むか**」
「**キーを産まなかったときどうするか**」のどれか。答えが 3 つ目なら `count.rs`、
2 つ目なら `select.rs`、1 つ目なら **このクレートには入らない**
（呼び出し側が `tally_reader` に述語として渡す）。

## モジュールを公開していない

`pub mod` ではなく **非公開モジュール + `lib.rs` での再エクスポート**にしている。

| 得られるもの | 内容 |
| --- | --- |
| 経路が 1 つ | `tally_core::Key` だけが正しい。`tally_core::select::Key` は存在しない |
| doc と semver の対象が明確 | 公開面は `lib.rs` の `pub use` 3 行を読めば全部分かる |
| 再エクスポート漏れが検出される | `pub` なのに外から到達できない項目は `unreachable_pub` が拾う |

**モジュールを分ける動機は公開面の設計ではなく、可視性の設計である。**
`Key::extract` / `needs_lowering` / `fold_case` / `snippet` / `SNIPPET_CHARS` は
すべて非公開で、**同じモジュールのテストからしか触れない。**

## テストの置き場所

**すべて `src/**` の `#[cfg(test)] mod tests`。** `tests/` ディレクトリを持たない。

理由: このクレートに **プロセスを起動しないと観測できないものが無い。**
`tests/` からは非公開項目が見えないため、
「借用が維持されているか」「文字境界で切れているか」といった検査は原理的に書けない。

**テストのために `pub` を付けない。** 公開 API は semver の対象であり、
検査の都合で広げると約束が増える。検査したい対象が非公開なら、テストを同じモジュールに置く。

CLI の統合テストは `crates/tally/tests/cli.rs` にある。

## 押さえておくべき設計判断

壊さないために、変更前に理由を把握しておくもの。
**公開 API の形は [ADR-0004](../../../docs/adr/0004-error-type-shape.md) と
[ADR-0005](../../../docs/adr/0005-selector-public-api.md) が正本**なので、
ここには結論だけ置く。

| 判断 | 理由 |
| --- | --- |
| **`clap` / `anyhow` に依存しない** | 依存の向きを一方向に保つ。逆流するとこのクレートを別の入口（サーバ、テスト）から使えなくなる |
| `Key` と `Selector` を分けている | 「どこから取るか」と「どう正規化するか」は別の関心事 |
| **`Selector` に入れてよいのは「参加する行がどうキーを産むか」だけ** | 「どの行が参加するか」は述語、「産まなかったときどうするか」は `Counter`。`Regex` は `PartialEq` を実装せず derive も壊れる |
| **`strict` が `Counter` にある** | 「産まなかったときどうするか」は抽出器の性質ではなく消費者の方針。同じ `Selector` を厳格にも緩くも回せる |
| **`Selector` / `Counter` のフィールドが非公開** | リテラル構築を封じるとフィールド追加が非破壊になる。`#[non_exhaustive]` は非公開フィールドがあれば冗長 |
| **`Key` に `#[non_exhaustive]`** | バリアントは増える側。定義元では属性が無効なので、内部の網羅性検査は保たれる |
| **`Key` / `Selector` の derive 4 つは公開の約束** | トレイト実装の削除は下流が自分では埋められない（孤児ルール）。「必要になるまで広げない」が効かない唯一の種類 |
| `Counter::on_missing` の `match` が `_` を使わず全バリアントを列挙 | `Key` に変種が増えたとき、`strict` が黙って無視されずコンパイルエラーになる |
| **抜粋を作るのは `LineError::new` だけ** | 切り詰めの規則（長さ・省略記号・文字境界）が散ると片方だけ直る |
| **`LineError` の `Display` は 1 行で自己完結し、`source()` は `kind` を飛ばす** | 素朴に `#[source] kind` と書くと連結表示で同じ文が 2 度出る。抜粋のエスケープは**単一エラーの `to_string()`** で成立していなければならない |
| **`serde_json::Error` を `JsonError` で隠す** | 公開依存にすると `serde_json` の major が版に波及する。enum のバリアントのフィールドは常に公開なので、型自体を不透明にするしか手がない |
| `JsonError` の `Display` が serde の行番号を落とす | 1 行ずつ渡すので serde の行番号は常に 1 になり、`LineError` の「N 行目」と衝突して読める |
| エラーの文字列が `String` でなく `Box<str>` | `Result` の大きさは最大バリアントで決まり、1 行ごとに 3 段返る。**失敗しない行も払う** |
| `fold_case` が `Cow` を返す | 変換不要なら借用のまま返す。無条件に `to_lowercase()` を呼ぶとテストが落ちる |
| **`tally_reader` が `Regex` ではなく `Fn(&str) -> bool` を受ける** | ここに正規表現の実装を持ち込まないため。テストも正規表現なしで書ける |
| 述語の境界が `FnMut` ではなく **`Fn`** | 状態を持つ述語（「最初の 10 行だけ」）を渡せると、フィルタが `limit` と競合する別機能になる |
| **`tally_reader` が `Counter` を引数で受ける** | `strict` の方針を決めるのは呼び出し側。内部で `Counter::new()` を作ると渡す手段が無くなる |
| **`enumerate` を `filter` より前に置く** | 行番号は入力の行番号でなければならない。後ろに置くと除外した行のぶんずれる |
| 集計結果に全順序を与えている | `HashMap` の反復順に依存すると出力が実行ごとに変わる |

## 新しいコードをどこに置くか

上から順に問う。**最初に「はい」になったところが置き場所。**

1. **`clap` か `anyhow` が要るか** → **このクレートではない。** `crates/tally/`
2. **ファイルやネットワークを開く必要があるか** → **このクレートではない。** `crates/tally/`
3. **失敗の種類を表す型か** → `src/error.rs`
4. **「参加する行がどうキーを産むか」の話か** → `src/select.rs`
5. **「キーを産まなかったときどうするか」または集計・結果の話か** → `src/count.rs`
6. **「どの行が参加するか」の話か** → **このクレートではない。** 述語として渡す

公開するかどうかは別の問い。**既定は非公開。**
公開するなら doc コメントと動くサンプルが要る（`missing_docs` が警告する）。
