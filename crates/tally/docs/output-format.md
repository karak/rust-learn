# tally の出力仕様

**利用者に対する契約。** ここに書いたことは、破ると利用者のパイプラインが壊れる。
変更するときは互換性を検討し、判断の過程は `docs/adr/` に記録する。

**ここに書くのは「何を保証するか」だけ。** なぜそう決めたかは ADR、
コードのどこにあるかは `layout.md`、実装が現に通っているかは `cargo t` が答える。

---

## 全形式に共通する保証

| 項目 | 保証 |
| --- | --- |
| **stdout の内容** | **集計結果のみ。** 診断・進捗・警告は一切出さない（すべて stderr へ） |
| 文字符号化 | UTF-8。BOM は付けない |
| 色・装飾 | stdout には付けない。端末かどうかに関わらず |
| **並び順** | **件数の降順。同数ならキーの昇順**（全順序が決まっており、実行ごとに変わらない） |
| 終了コード | 成功 `0` / 実行時エラー `1` / 引数の誤り `2`（clap） |
| 出力が空の場合 | 何も出さない。空行も出さない |

**並び順は契約である。** `HashMap` の反復順に依存させず、同数時のタイブレークまで
決めてあるので、同じ入力に対して常に同じバイト列が出る。

## `--format text`（既定）

```
件数<TAB>キー<LF>
```

- 区切りは **タブ 1 個**。空白ではない
- 各行は LF で終わる。**最終行にも LF が付く**
- ヘッダ行は無い
- キーに含まれるタブや改行は **エスケープしない**（そのまま出す）

例:

```
3	info
1	warn
```

**キーにタブが含まれうる入力では、この形式は曖昧になる。**
その場合は `csv` か `json` を使うこと。

---

## `--format csv`

RFC 4180 の部分集合。**逸脱を 2 点含む**（判断は
[ADR-0003](../../../docs/adr/0003-csv-output-contract.md)）。

```
件数,キー<LF>
```

- **ヘッダ行を出さない。** 1 行目からデータである
- **改行は LF。** RFC 4180 が定める CRLF ではない
- 区切りは `,`
- **引用は必要なときだけ。** 値が `,` `"` CR LF のいずれかを含むときのみ
  二重引用符で囲む。含まれる `"` は `""` に倍化する

例:

```
3,info
1,"key,with,commas"
2,"say ""hi"""
```

**表計算に取り込むと列名が付かない。** 必要なら利用者側で付けること。

## `--format json`

```json
{
  "entries": [
    { "key": "info", "count": 3 }
  ],
  "skipped": 0,
  "total": 4
}
```

**保証すること:**

- 最上位はオブジェクト。キーは `entries` / `skipped` / `total` の 3 つ
- `entries` は配列。各要素は `key`（文字列）と `count`（非負整数）を持つ
- `entries` の順序は共通の並び順に従う
- `total` は読んだ行数（空行を除く）、`skipped` はキーを取り出せなかった行数
- **出力の末尾に LF が付く**（パイプで繋いだ次の出力と行が繋がらないため）

**保証しないこと:**

- **インデントや空白の入り方。** 整形は変わりうる。
  文字列として突き合わせず、JSON として解釈して値を見ること
- オブジェクト内のキーの出現順

---

## `--stats`

集計対象の行数とスキップ行数を **stderr** に出す。
**stdout は変化しない。** パイプの下流に影響しない。

---

## 互換性の考え方

- **保証していないものに依存しない。** JSON の空白は変わりうる
- 新しい形式の追加は後方互換。既存形式の出力を変えるのは破壊的変更
- **緩める方向は互換、厳しくする方向は破壊的。**
  例: ヘッダを付けない → 付ける は追加なので移行しやすいが、
  付けている → 付けない は既存の利用者を壊す。**厳しい側から始めている**
