# 記録の判断を本に書き直すときは、理由を記録から写し、もっともらしい一般論に替えない

**得た日**: 2026-11-27（付録 C を後からレビューしたとき）

## 学び

付録 C は、`miri` を `tally` 本体に当てなかった理由を「`miri` は既定で OS 呼び出しやファイル・プロセス起動を制限しているため」と書いていた。
記録（`stage-log.md` 段階 8 と `learning-log.md` 14-4）の理由は時間である。`tally-core` の単体テストで通常のおよそ 16 倍かかり、プロセス起動とファイル I/O を含む層では現実的な時間にならないと判断していた。
隔離の挙動はどの記録にも無く、試してもいなかった。

書き換えた理由は、`miri` の一般的な性質としては正しいので、読んでも引っかからない。
本が正本ではない以上、判断の理由は記録が持つものを写すのが筋で、書き手が思いつく別の理由に差し替えると、記録と本が食い違ったまま残る。

## 改善候補

- 本に「〜しなかった」「〜を選んだ」と書くときは、その理由の文を記録の該当箇所から探し、同じ理由を書く
- 記録に無い理由を足したくなったら、試したかどうかを書き分け、試していなければ「試していない」と書く
