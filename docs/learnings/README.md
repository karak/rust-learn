# 学びの受け渡し（`docs/learnings/`）

作業の中で得た学びと改善候補を、1 件 1 ファイルで置く場所。
**連携先のピアへの受け渡しは、ここに書いたものだけで行う。**
2026-11-22 から始めた（[ADR-0013](../adr/0013-book-phase.md) 論点 8）。

## 取り決め

連携先のピアから受け取った固定文を、そのまま写す（2026-11-21 受領、学習者の承認）。

> 作業の中で得た学び・改善候補は、`docs/learnings/` に、件ごとに一意で変わらない id を付けて書いてください。追記のみで、書いた件は書き換えず、誤りは新しい件で正してください。同じ学びを別の id で書き直さないよう、書く前に既にある件を見てください。作業の区切りと、セッションを終える前に、書き漏らした学びが無いかを見てください。メッセージで送られた学びは、ここに書かれるまで受け取られません。件は、この repo の手元の `origin/main` に入った時点で受け取られます。`main` を push すればそのまま入り、remote で merge した時は `git fetch` するまで入りません。入ったら、受け取る相手に「新しい件がある」とだけ知らせてください。`2026-11-22` より前に得た学びは書かないでください。この取り決めは、起動した時に自分が読む案件側の記録に書き留めてください。

補足（同じく受領したもの）:

- 1 件 1 ファイルにし、**拡張子を除いたファイル名を件の id にする。** この README は件に数えない
- 受け取る相手は、herdr のラベルで決まる pane のセッション。
  **ラベルの値はこのリポジトリに書かない**（リポジトリに入れないと決めた語を含むため）

## このリポジトリでの書き方

- **ファイル名は `YYYY-MM-DD-<短い説明>.md`。** 日付は学びを得た日、説明は ASCII の kebab-case。
  一度付けた名前は変えない
- **journal と二重にしない。** その日の振り返り（KPT）は `docs/journal/` に書き、
  そこで出た学びや改善候補は件としてここに書く。journal からは件の id をコード書式で書いて指す
  （例: `2026-11-22-short-description`）
- **件には相対リンクとテストのフルパス（`::tests::`）を書かない。** どちらも `scripts/check-docs.sh` が検査するので、
  リンク先が動くと、書き換えられない件のせいで CI が落ちる
- **件もトピックブランチに載せる**（`main` に直接コミットしない。`CLAUDE.md`「ブランチ運用」）。
  受け取られるのは、`main` に `--ff-only` で取り込んで push したときである
- 件が `origin/main` に入ったら、受け取る相手に「新しい件がある」とだけ知らせる

## 書かないもの

- **2026-11-22 より前に得た学び**
- **書いた件の書き換え。** 誤りは新しい件で正し、古い件の id を挙げる
- **既にある件の言い直し。** 書く前に、このディレクトリを見る
- **現在地や未決事項**（`docs/handoff.md`）、**リポジトリの規約**（`CLAUDE.md`）

## 検査にできるか

| 書かないこと | 検査 |
| --- | --- |
| ファイル名の形が違う、日付が 2026-11-22 より前 | **できる。** `scripts/check-docs.sh` の検査 8 |
| 書いた件の書き換え・削除・改名 | **足していない。** `origin/main` との差分で見られるが、CI は浅く取得するので `origin/main` が手元に無い |
| 既にある件の言い直し | **できない。** 同じ意味かどうかは字面で決まらない |
