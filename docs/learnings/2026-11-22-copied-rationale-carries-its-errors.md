# 本物のコメントが述べる理由を写すときは、その理由も確かめる

**得た日**: 2026-11-22（本の第 11 章を書いたとき）

## 学び

本の「本物ではどうなっているか」で、`tally` が書き出しの失敗の連鎖をたどって `BrokenPipe` を探す理由を、
コードのドキュメントコメントから写した。「`serde_json` を通して書き出すと、`io::Error` が `serde_json::Error` に包まれて届くことがある」。

レビュアーが依存先のソースで確かめると、`io::Result` へ `?` で戻す経路では、`serde_json` は包みを外して元の `io::Error` を返していた。
包まれたまま届いたとしても、`serde_json::Error` の `source()` は中の `io::Error` を指さないので、たどっても見つからない。
写した理由は、写す前から誤っていた。

コード（何をしているか）はテストが確かめているが、コメント（なぜそうしたか）は何も確かめていない。
本物から写す断定のうち、コメントが述べる理由だけは、確かめていない文として扱う必要があった。

## 改善候補

- 本物のコメントから理由を写すときは、依存先の挙動を述べた部分を、依存先のソースか小さな実験で確かめる
- 確かめられないなら、理由を写さず、コードが何をしているかだけを書く
- 誤りを見つけたコメントは、既存コメントの扱いの規則に従い、学習者に直すかを尋ねる
