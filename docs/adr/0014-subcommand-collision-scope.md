# ADR-0009 論点 2 の「位置引数と衝突する」の範囲を正す

**`status` は `accepted`**（2026-11-27）。
[ADR-0009](0009-release-distribution.md) 論点 2 の**決定は変えない。**
正すのは、その決定に効いた事実の書き方である。

## なぜこれを ADR にするのか

**ADR-0009 は `accepted` で、決定の記述は書き換えない**（[ADR-0001](0001-record-architecture-decisions.md)）。
今回の誤りは誤字ではなく、**実測の結果を実測より広く書いた**ものである。
直した事実と、それでも決定が変わらない理由を、ADR-0009 の改訂ではなく 1 本の記録として残す。

## コンテキストと問題提起

ADR-0009 論点 2 は、可変個の位置引数（`inputs: Vec<PathBuf>`）と `completions` サブコマンドを同居させた clap 4.6.6 の最小例で、
次の 4 通りを確かめていた（2026-10-12）。

- `prog completions bash` → サブコマンドとして解釈される
- `prog completions` → `MissingRequiredArgument <SHELL>` で失敗する
- `prog -- completions` → 位置引数として通る
- `prog a.log b.log` → 位置引数として通る

ここから案 2a の欠点を **「`completions` / `man` という名前のファイルが `--` なしで渡せなくなる」**と書いた。
**`completions` が先頭以外にある場合は試していなかった。**

2026-11-27、本の付録 B のレビューでこの範囲の言い過ぎを指摘され、同じ形の最小例（clap 4.6.6）で確かめ直した。

| 叩き方 | 結果 |
| --- | --- |
| `prog completions` | `MissingRequiredArgument` で失敗 |
| `prog a.log completions` | **位置引数として通る**（`inputs` は `["a.log", "completions"]`） |
| `prog ./completions` | **位置引数として通る** |
| `prog -- completions` | 位置引数として通る |

**サブコマンドと解釈されるのは、`completions` が先頭の位置引数にあるときだけだった。**

## 決定

**ADR-0009 論点 2 の案 2a の欠点を、次のように読み替える。**

> `completions` / `man` という名前のファイルを、`--` も `./` も付けずに**先頭の位置引数として**渡せなくなる。

**論点 2 の決定（生成専用のバイナリをワークスペースに置き、`tally` 本体の CLI 表面は変えない）は変えない。**

## 決定が変わらない理由

- **衝突は狭くなったが、無くなってはいない。** `tally completions` は、`completions` というファイル 1 つを集計する、もっとも素直な叩き方である。
  そこで「シェルの名前が要る」という無関係な診断が出ることは、ADR-0009 が問題にした点そのままである
- **案 2a のもう 1 つの欠点は、衝突の範囲に依らない。** サブコマンドを持つと `--help` の構造が変わり、外部の契約が変わる
- **案 2a の利点も変わらない。** 利点の側は衝突の範囲を前提にしていない

## 検討した案

### A. ADR-0009 を「明確化」として直接直す（採らない）

ADR-0001 は `accepted` の ADR に、決定を変えない明確化を許している。
**ただし今回は、実測の範囲を超えて書いた事実の訂正であり、決定の根拠の一部を言い直す。**
根拠の書き換えを明確化の枠に入れると、どこまでが明確化かが曖昧になる（`docs/handoff.md` 未決事項 10 と同じ形の穴）。
学習者の判断で、新しい ADR にした。

### B. 新しい ADR で範囲を正し、ADR-0009 からは指し先だけを足す（採る）

**ADR-0009 の本文の記述は書き換えない。** 冒頭の注記と改訂履歴に、この ADR への指し先だけを足す（ADR-0004 が ADR-0007 を指したのと同じ形）。

## 帰結

- 本の付録 B は、すでに「先頭の位置引数に渡したとき」と範囲を付けている（2026-11-27）。本と記録の食い違いは、この ADR で閉じる
- **言い過ぎの形は、件 `2026-11-22-negative-claims-hide-escape-hatches` と同じ**である。「渡せなくなる」という否定を、試した 1 通りから全体へ広げていた
