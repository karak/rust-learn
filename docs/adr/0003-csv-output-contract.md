# CSV 出力の仕様: ヘッダ行を付けず、改行は LF とする

## コンテキストと問題提起

段階 3 で `--format csv` を追加する。RFC 4180 は CSV の骨格を定めるが、
**実装が決めなければならない点を明示的に任意にしている。**

- **ヘッダ行**: 「There maybe an optional header line」と規定され、
  有無は MIME パラメータ `header=present|absent` で伝えるべきものとされる。
  パラメータを使わない場合、受け手が自分で判断するしかない
- **改行**: RFC 4180 は CRLF を規定する

`tally` の出力は他のツールへパイプで渡すことを前提としている。
この前提と CSV の慣習が衝突する点を、先に決めておく必要がある。

## 意思決定の推進力

* **stdout はデータ専用でバイト透過に保つ。** 既存の設計判断
  （`crates/tally/docs/layout.md`）であり、統合テストが stdout の完全一致で守っている
* **既存の text 形式との対称性。** text にヘッダは無い
* **Unix パイプラインでの合成可能性。** `sort` / `head` / `wc -l` が素直に働くこと

## 決定

### 1. ヘッダ行を付けない

**`count,key` のようなヘッダ行を出力しない。**

### 2. 改行は LF（`\n`）とする

RFC 4180 の CRLF から**意図的に逸脱する**。

### 3. 引用は必要なときだけ行う

値が **区切り文字（`,`）・二重引用符（`"`）・CR・LF** のいずれかを含むときだけ
二重引用符で囲む。含まれる `"` は `""` に倍化する。それ以外は裸で出す。

## 帰結

### 正の影響

* **パイプラインが壊れない。** ヘッダがあると `sort` はそれをデータ行として並べ替え、
  `wc -l` は 1 多く数え、`head -1` は最初のデータではなくヘッダを返す
* **text 形式と非対称にならない。** どちらも「1 行 = 1 レコード」で一貫する
* LF は Unix 系ツールの既定であり、`awk` や `cut` がそのまま使える
* 必要なときだけ引用するので、大半の行が短くなり目視しやすい

### 負の影響

* **表計算ソフトに取り込んだとき、列名が付かない。** 利用者が自分で付ける必要がある
* **RFC 4180 に厳密には準拠しない**（改行が CRLF でない）。
  厳密な準拠を要求する受け手には適さない
* ヘッダを期待するツールに渡すと、最初のデータ行がヘッダとして解釈されうる

### 確認方法

- ヘッダを出さないことを、統合テストで stdout の完全一致により検査する
- 引用が必要な値（`,` `"` CR LF を含む）と不要な値の両方をユニットテストで検査する
- 外部仕様は `crates/tally/docs/output-format.md` に記述し、そこを正本とする

## 検討した代替案

### ヘッダ行を常に出す

* Good, because 表計算・pandas・csvkit が列名を認識する
* Good, because CSV の慣習としては自然
* Bad, because **パイプラインでヘッダがデータ行になる。**
  `tally --format csv | sort -t, -k1 -rn` が壊れる
* Bad, because text 形式と非対称になる

### `--csv-header` フラグで選べるようにする

* Good, because 両方の用途に応えられる
* Bad, because **フラグが 1 つ増える。** 現時点で要求が無いのに選択肢を増やすと、
  組み合わせの検査対象も増える
* Bad, because 既定値をどちらにしても、結局この ADR と同じ判断が要る

**必要になったら足せる。** 付けない状態から付ける状態への移行は後方互換だが、
逆（既定で付けていたものを外す）は破壊的変更になる。**厳しい側から始める。**

## 追加情報

判断が変わる条件:

- 表計算への取り込みが主要な用途になったら、`--csv-header` を再検討する
- RFC 4180 への厳密準拠を要求する連携先が現れたら、改行を再検討する

この決定により、`Formatter` に `write_header` のような操作を足す必要は生じない。
[ADR-0002](0002-output-format-abstraction.md) の D3（操作追加のコスト）は
**投機のまま**であり、重みは低いまま据え置く。

外部仕様の本文は `crates/tally/docs/output-format.md`。本 ADR は
**なぜそう決めたか**を持ち、仕様そのものは持たない。
