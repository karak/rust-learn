# 本の章のレビュー

**機械で見えるものは検査に任せ、レビュアーには判断の要るものだけを見せる。**

機械が見るもの（レビュアーに頼まない）:

- `scripts/check-docs.sh` — 本に書かないもの、太字とリンクの順、9 章までのコードのライフタイム注釈
- `cd book && npm run build` — まだ無い章へのリンク、切れたアンカー

## 手順

1. 書く前に、章の構成と「確かめる断定の一覧」を書き出す
2. 一覧の断定を手元で実行して確かめる。下の **範囲** を満たすまで
3. 本文とコードを書き、`scripts/check-docs.sh` と本のビルドを通す
4. 別モデルの読むだけのレビュアーに、差分と下の **判断の要る点** を渡す。
   指摘には、ファイルと行、どの点か、確かめた根拠（実行結果や前の章の該当行）を付けさせる
5. 指摘を直し、**直した文も実行して確かめる**。直したあとにもう一度レビュアーに見せる。完了の条件は、指摘がすべて「直した」か「直さない理由を書いた」になっていること

## 判断の要る点

**範囲**: 確かめた事実を、確かめた範囲で書いているか。

- 断定ごとに、代表の 1 例に加えて **成り立たない入力**（空、境界、別の書き方）を 1 つ試したか。第 3 章のレビューで拾われた言い過ぎの多くは、代表の 1 例しか試していなかったことによる
- 第 3 章では「空文字列は確保しない」「`let` の右辺で直接 `&` を付ければ寿命が延びる」の範囲を書き落としていた

**比較**: 他言語の例が、主張どおりに壊れるか。

- C++ の例は実行して確かめる。第 3 章では短い文字列が SSO に収まり、主張した再確保が起きなかった
- 「〜してよい」（規格が許す）と「必ず〜する」を書き分けているか。第 3 章では `std::string` の `+=` が「参照を無効にしてよい操作」であって「必ず無効にする操作」ではなかった
- コンパイラの警告は、どの形に出てどの形に出ないかまで試したか。第 3 章では clang の警告が一時オブジェクトの形にしか出なかった
- 保証を述べるとき、例外になる型や操作を外しているか。第 2 章では `unordered_map` の `erase` が「反復子を 1 つだけ無効にする」ところまでと、`&T` の保証から内部可変性を持つ型を外すことを書き分ける必要があった

**未習**: まだ出していない概念を、説明なしで使っていないか。

- 本文に出た用語を前の章のファイルで grep する。初出なら説明を足すか、扱う章の番号を文で書く
- 第 3 章では `Option`、panic、`unsafe` が説明なしで出ていた

**用語集**: [ADR-0013](../../../docs/adr/0013-book-phase.md) 論点 9 の決まりに沿っているか。

- 論点 9 の決まり（リンクを張る箇所、項目の書き方）を、差分に出たリンクと用語集の項目の 1 つずつに当てる
